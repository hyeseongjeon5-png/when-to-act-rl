## 2. 지금까지 바뀐 결론 (이걸 전제로 시작한다)

### MountainCar — 더 단단해졌다

λ\* = 0 (세 계열 모두). **비용이 없어도 학습이 pump 규칙을 넘어서지 못한다.**
- 예산을 3.3배로 늘려도, ε를 감소시켜도, 신경망을 키워도 마찬가지 (#11)
- 기준 규칙(pump)은 감사 결과 **이미 최선**이었다 — 약한 상대를 세운 것이 아니다
- ε 감소는 **오히려 해로웠다** (완전 실패 1/5 → 2/5). 무작위 탐험 도달률이 0.0%인 환경이라
  ε가 클 때의 행동은 정보를 주지 못하고 예산만 쓴다

### LunarLander — 결론이 바뀌었다 ★

**처음 기준 규칙이 너무 약했다.** 계수를 다시 고르자(평가에 쓰지 않는 에피소드에서 튜닝)
r IQM 38.3 → 179.8. 그 결과 λ\*가 이렇게 바뀌었다.

| 계열 | 전 | 후 |
|---|---|---|
| 표준 DQN | 2.0 | **1.0** |
| Lazy-MDP | 2.0 | 2.0 |
| TempoRL | 2.0 | **0** — 비용이 없어도 못 이긴다 |

### 무행동 붕괴는 두 단계다 ★

표준 DQN은 λ=0.0075에서 **행동 120회를 유지하면서 도달률만 62% → 9%** 로 떨어진다.
행동이 줄어드는 것은 λ=0.01부터, 완전히 멈추는 것은 0.03부터다.
**시도를 멈추는 것이 아니라 성공을 멈춘다.**

## 4. 이 스프린트에서 얻은 규칙 (다음에도 지킬 것)

1. 지문(설정 해시)에 항목을 추가할 때는 기본값에서 기존 해시가 보존되는지 먼저 확인한다
2. 윈도우에서 상태 파일을 원자적으로 갱신할 때는 반드시 재시도를 붙인다.
   **상태 기록 실패가 계산을 중단시키지 않게 한다**
3. 자동으로 무언가를 실행하는 장치는 무장 전에 판단 근거가 맞는지 확인한다. **모르면 움직이지 않는다**
4. 명령이 없을 때(`command not found`)와 결과가 0일 때를 구분한다
5. 상태를 가진 기본 정책은 매 스텝 호출한다
6. 곡선 평가 한 점으로 판단하지 않는다 — 최종 평가로 확인한다
7. **주장하기 전에 확인한다** (재현성·서지·수치 출처 전부)
8. **비교 상대에도 공을 들인다.** 학습만 의심하고 규칙은 의심하지 않으면 결론이 부풀려진다
9. **검사를 만들면 일부러 실패시켜 본다.** 통과하는 것을 보고 안심하지 않는다.
   아무것도 못 찾는 것과 문제가 없는 것은 다르다 (사고 3·4가 같은 뿌리다)
10. **몇 분 넘게 걸리는 것은 `nohup`으로 돌리고 로그를 감시한다.**
    도구의 백그라운드 실행은 중단될 수 있다 — 실제로 집계와 전환비용 재측정이
    한 번씩 쓰기 전에 죽었다. 결과 파일은 원자적 쓰기 덕에 온전했지만, 시간을 버렸다
11. **자동 생성되지 않는 숫자에는 반드시 검사를 붙인다.**
    이 스프린트에서 발견한 수치 결함 5건이 전부 사람이 쓴 문장에서 나왔다
    (잣대 불일치 · 출처 없는 배수 · 단위 오류 · 낡은 규칙 점수 2건).
    자동 생성되는 Ⅳ장에서는 하나도 나오지 않았다
