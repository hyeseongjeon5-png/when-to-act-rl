# 깃허브 등록·운영 가이드

결론 먼저: 채용에서 보는 것은 별이 아니라 **"꾸준히, 의미 있는 단위로, 설명하면서 일했는가"** 다.
커밋 이력·이슈·README 세 가지만 관리하면 된다. 세부 규칙은 `.claude/skills/github-project-log` 스킬 참조.

## 1. 최초 등록 (한 번만)

깃허브 웹에서 새 저장소를 만들지 말고, 아래를 이 폴더에서 실행 (저장소 이름 제안: `when-to-act-rl`):

```powershell
git init
git add .
git commit -m "chore: 프로젝트 초기 구조 (실험 설계·로드맵·비용 래퍼·기준선 뼈대)"
git branch -M main

# gh CLI가 있으면 (없으면 winget install GitHub.cli 후 gh auth login)
gh repo create when-to-act-rl --public --source=. --push
```

gh가 안 되면: github.com에서 빈 public 저장소 `when-to-act-rl` 생성(README 없이) 후

```powershell
git remote add origin https://github.com/<내아이디>/when-to-act-rl.git
git push -u origin main
```

## 2. 등록 직후 할 것 (10분)

1. 저장소 Settings → 없음. About 칸에 한 줄 설명 + 토픽 추가: `reinforcement-learning`, `dqn`, `gymnasium`, `pytorch`, `thesis`
2. Issues 켜고 마일스톤 3개 생성: `1주차 기준선`, `2주차 선행연구 재현`, `3주차 본실험 1차` (docs/03_로드맵.md 그대로)
3. 로드맵의 할 일을 이슈로 등록 (실험 1개 = 이슈 1개)

## 3. 평소 리듬

- 작업한 날은 **하루 1커밋 이상** (작더라도). 3주간 잔디가 이 프로젝트의 성실함 증거가 된다
- 커밋 메시지: `종류: 내용` — `feat:`(기능) `exp:`(실험 실행/결과) `fix:` `docs:` `refactor:`
  - 좋은 예: `exp: MountainCar λ격자 파일럿 (3λ×3시드, 결과 results/pilot1)`
- 실험 이슈는 **결과 요약(수치+그림)을 코멘트로 달고 닫는다** — 나중에 논문 쓸 때 그대로 재료가 됨
- 주 1회 README의 '진행 상황' 체크박스 갱신
- 큰 기능(TempoRL 이식 등)은 브랜치 → Pull Request → 스스로 머지. PR 본문에 무엇을·왜 했는지 남기면 평가자가 보기 좋다

## 4. 절대 커밋하면 안 되는 것

- `.env`, API 키 (이 프로젝트엔 없어야 정상)
- `results/raw/`, 모델 체크포인트(*.pt) — .gitignore가 막고 있는지 `git status`로 확인
- 학교 제출 서식 원본(개인정보·결재란 포함 PDF) — 요약본(docs/01)만 공개
